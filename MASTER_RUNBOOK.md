## SECTION 1: SYSTEM REQUIREMENTS

The CAPVIA platform relies on the following toolchain versions. Do not install incompatible versions (such as Python 3.14) to prevent dependency compilation issues.

### Required Software Versions
*   **Operating System**: macOS (tested on Sonoma/Sequoia, Apple Silicon and Intel)
*   **Python**: `3.12.x` (FastAPI backends)
*   **Node.js**: `v20.x.x` (LTS)
*   **npm**: `10.x.x` (included with Node 20)
*   **PostgreSQL**: `15.x` (Relational storage)
*   **MongoDB**: `6.x` or `7.x` Community Edition (ATS MongoDB storage)
*   **Redis**: `7.x` (caching & Celery task broker)
*   **Docker**: Docker Desktop (for containerized execution tests)

## SECTION 6: REDIS

### How Redis is Used in CAPVIA
1.  **Email Verification & Password Reset**: The gateway stores verification tokens (TTL: 24h) and reset tokens (TTL: 15m) in database index 0 (`redis://localhost:6379/0`).
2.  **Telemetry Analysis Cache**: ATS and Simulation results are stored in Redis (`status:<id>`, `full_result:<id>`, `score:<id>`) for instant rendering.
3.  **Celery Queue Broker**: The simulation worker uses database index 1 (`/1`) as the Celery broker, and index 2 (`/2`) to persist task results.

### Verification of Redis Connectivity
Start the Redis server if it isn't running and ping it to check for response:
```bash
# Check ping
redis-cli ping
# Expected: PONG

# Inspect stored keys in database 0
redis-cli -n 0 keys "*"
```

## SECTION 10: FULL APPLICATION FLOW

Follow these steps to trace a candidate's complete recruitment cycle:

### 1. Create HR
*   **Action**: Recruiters are seeded into PostgreSQL via database seed.
*   **Expected Database Changes**: Row added to `users` with `role = 'HR'`, `email = 'hr@capvia.ai'`, `is_active = true`.
*   **Expected API Calls**: None (database seed execution).
*   **Expected Frontend Behavior**: Pre-seeded user `hr@capvia.ai` can log in successfully.
*   **Expected Logs**: `Seeded Users: Recruiter Jane Smith`.

### 2. Create Company
*   **Action**: HR logs in and creates a company.
*   **Expected Database Changes**: Row added to `companies`. Row added to `company_members` mapping HR as `OWNER`.
*   **Expected API Calls**: `POST http://localhost:8000/api/v1/companies` (Authenticated with Recruiter Token).
*   **Expected Frontend Behavior**: Recruiter Dashboard displays "Company Created Successfully" and shows the profile.
*   **Expected Logs**: `CompanyService` persists the company details.

### 3. Create Internship
*   **Action**: HR creates a "Backend Developer" internship listing.
*   **Expected Database Changes**: Row added to `internships`. Row added to `vacancy_mappings` with unique UUID mappings for subsystems.
*   **Expected API Calls**: `POST http://localhost:8000/api/v1/internships`
*   **Expected Frontend Behavior**: Form submits, listing shows on recruiter page.
*   **Expected Logs**: `Seeded Internship: Backend Developer`.

### 4. Create Candidate
*   **Action**: Candidate registers and verifies email.
*   **Expected Database Changes**: Row added to `users` with `role = 'STUDENT'`, `is_active = false`. Redis key `email_verify:<token>` is set. Upon verification, `is_active = true`, and a mapping is written to `candidate_mappings`.
*   **Expected API Calls**: `POST http://localhost:8000/api/v1/auth/register`, followed by `POST http://localhost:8000/api/v1/auth/verify-email`.
*   **Expected Frontend Behavior**: Page displays verification link generated on CLI. Upon confirmation, the login portal opens.
*   **Expected Logs**: `[SIMULATED EMAIL SENDER] Verification link for candidate@example.com: http://localhost:3000/auth/verify?token=...`

### 5. Apply
*   **Action**: Candidate applies for the "Backend Developer" internship.
*   **Expected Database Changes**: Row added to `applications` with `status = 'APPLIED'` and `current_stage = 'ATS'`. Row added to `application_mappings`.
*   **Expected API Calls**: `POST http://localhost:8000/api/v1/internships/{internship_id}/apply`
*   **Expected Frontend Behavior**: UI dashboard updates to show "ATS Resume Screening Stage".
*   **Expected Logs**: `Application created successfully`.

### 6. Resume Upload
*   **Action**: Candidate uploads a PDF resume.
*   **Expected Database Changes**: `applications.status` transitions to `ATS_PENDING`. Resume metadata record saved in the local ATS PostgreSQL.
*   **Expected API Calls**:
    1.  Core calls ATS: `POST http://localhost:8001/api/v1/resume/upload`
    2.  ATS uploads to S3 bucket `capvia-resumes-dev`.
*   **Expected Frontend Behavior**: Screen displays "File Uploaded. Reviewing formatting...".
*   **Expected Logs**: `ATS API Call: POST /api/v1/resume/upload` -> `resume_uploaded_and_queued`.

### 7. ATS Screening
*   **Action**: ATS completes parsing and sends a webhook to Core Gateway.
*   **Expected Database Changes**:
    *   Row added to `ats_results` with score, matched skills, gaps, and fraud flags.
    *   `application_mappings` caches `ats_score` and `ats_resume_uuid`.
    *   `applications.status` updates to `ATS_COMPLETED`.
    *   If score >= 60% and not suspicious, `applications.status` transitions to `SIMULATION_INVITED`.
*   **Expected API Calls**:

## SECTION 11: COMMON FAILURES & RESOLUTIONS

### 1. Port Collisions (Port 3000/3001/3002)
*   **Symptom**: Starting Next.js recruiter dashboard throws port error or collides with ATS frontend.
*   **Root Cause**: Both applications run Next.js which defaults to port 3000.
*   **Resolution**: Set the `PORT` environment variable explicitly on startup and call Next.js directly:
    *   Recruiter Dashboard: `PORT=3000 node node_modules/next/dist/bin/next dev`
    *   ATS Frontend: `PORT=3001 node node_modules/next/dist/bin/next dev`
    *   AI Interview Kiosk (Dev Mode): `PORT=3002 npm run electron:dev`

### 2. exFAT Partition Module & Virtual Env Failures (napi-postinstall errors)
*   **Symptom**: Running `npm install` throws `sh: napi-postinstall: command not found` (or code 127), or `pip install` throws path/compilation errors.
*   **Root Cause**: External exFAT drives do not support symlinks, which breaks virtualenv mappings. For Node/npm, avoiding symlinks with `--no-bin-links` prevents the creation of binary symlinks in `node_modules/.bin`. When packages with native binaries attempt to run postinstall checks (e.g. `napi-postinstall`), the shell cannot locate the executable in the path, causing installation failures.
*   **Resolution**:
    *   **Python**: Initialize all virtual environments in the home directory (`~/` which uses APFS):
        ```bash
        python3.12 -m venv ~/my_venv
        ```
    *   **Node/npm**: Execute installations with both `--no-bin-links` and `--ignore-scripts` to bypass failing postinstall tasks:
        ```bash
        npm install --no-bin-links --ignore-scripts
        ```

### 3. Electron Startup Failure ("Electron failed to install correctly")
*   **Symptom**: Running Electron throws `Error: Electron failed to install correctly, please delete node_modules/electron and try installing again`.
*   **Root Cause**: Using the `--ignore-scripts` flag during dependency installation skips the postinstall script (`node install.js`) responsible for downloading the compiled platform-specific Electron binary.
*   **Resolution**: Run the download script manually inside the `ai_interview` directory:
    ```bash
    node node_modules/electron/install.js
    ```
    Once the download completes, relaunch the application.

### 4. Missing PostgreSQL pgvector Extension
*   **Symptom**: ATS or Central backend starts but crashes on database initialization due to unknown type `vector`.
*   **Root Cause**: PostgreSQL requires the pgvector extension to compile embedding columns.
*   **Resolution**: Ensure PostgreSQL has pgvector installed. (In Homebrew Postgres, it is bundled or can be installed via `brew install pgvector` if needed).

### 4. Local Ollama Server Offline
*   **Symptom**: Video interview kiosk fails to generate dynamic interview questions.
*   **Root Cause**: Ollama is offline or the target model is not pulled.
*   **Resolution**: Kiosk automatically handles this by falling back to the cached question template bank (`localQuestionAI.ts`), generating role-specific questions from local pools.

### 5. Evaluation Server Offline (Port 8765)
*   **Symptom**: Complete video interview fails to score and hangs.
*   **Root Cause**: AI Interview Evaluation server is offline.
*   **Resolution**: The kiosk React client automatically switches to client-side scoring logic to produce a baseline. It submits the interview with `baselined_locally=true` and passes the baseline scores. CAPVIA Core saves this baseline and queues it for server-side evaluation once the server recovers.
